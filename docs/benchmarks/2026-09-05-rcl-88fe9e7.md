# 从零到 RCL8 基准（线上版本 88fe9e7 = 1788530763832）— 终报

母房 W33S7 从空 Memory、单 spawn 跑到 RCL8：**1,208,082 tick**。私服墙钟 58.46 小时（5.7 tick/s，中途 CLI 超时重启 7 次，世界未丢）。线上 shard1 实测 3.8 秒/tick（`logs/status.jsonl` 105 小时 / 101k tick），合 **53.1 天**。
数据表（脚本从完整跑生成）：[2026-09-05-rcl-88fe9e7-tables.md](2026-09-05-rcl-88fe9e7-tables.md)。原始采样在 `data/soak/rcl-bench-88fe9e7/`（gitignore），看板 `python3 scripts/soak/rcl_dashboard.py --run data/soak/rcl-bench-88fe9e7 --port 8765`。
160k 之前的段落是中期核验（16 个对抗 agent 复算）留下的，数字没有改；RCL7/8、账号总账和终态建筑以终报和数据表为准。单位：未注明的能量数即能量；1 能量升级 = 1 CP（无 boost 时引擎严格相等）。"占收入"的分母 = 采集 + spawn 自产（≈1/tick）+ 初始 300。

## 结论

- **母房 W33S7 到各级的 tick（终值）**：RCL2 @1,229 · RCL3 @27,092 · RCL4 @43,707 · RCL5 @86,730 · RCL6 @159,101 · **RCL7 @374,041**（本级 214,940 tick，17.0 CP/tick）· **RCL8 @1,208,082**（本级 834,041 tick，13.1 CP/tick）。线上按 3.8 秒/tick：**53.1 天**。中期按 14.4/19/25 CP/tick 外推的 RCL8 区间是 0.74M–1.17M；实际 1.208M，落在悲观端之外——RCL7 阶段母房升级掉到 13.1/tick，主因是工地名额被死房占满、三个房反复降级、占领流水线卡死，不是两源产能不够。
- **前三级是最差的一段**：RCL2→3 用了 25,863 tick，是"两源全投控制器"下限（2,250）的 11 倍，效率 9%。25k tick 内没建一个 extension（先铺了 83 条路和 3 个容器），spawn 容量卡在 300，后半段 spawn 有 63–73% 的采样满着 300 能量却空闲；能量堆在地上（平均 3.1k、峰值 8.5k），这一级 49% 的收入进了残差，其中地面衰减估计至少 27%。RCL3 建了 10 个 extension 后升级速率从 1.7 跳到 8.1 CP/tick，源利用率 96%。
- **RCL4 起账号开始占领**：6 个房在 tick 45k–70k 每轮大脑一个占下，第 7 个在 90k；母房自己的进度只用了自家收入（两源 + 自家外矿）的 24–29%，其余给了新房和外矿。**账号总 CP 从 8/tick 升到稳态 73–83/tick**（130k–160k 窗口平均 77.6），总 CP 占采集 40–47%（均 43%）、孵化占采集 32–34%——这个比例已接近 Kalgen（控制器 38%、creep 33%）。
- **但 8 个房只有 6 个在产出**：稳态各房 CP/tick 为 W33S7 19.0、W31S8 16.7、W34S7 13.7、W31S5 10.8、W31S6 9.4、W34S9 7.9、W35S7 0.3、W33S8 0.0。两个死房（见"故障"）按其它 5 个新房的均值 11.7 算，少了约 23–26 CP/tick。
- **外矿净赚但很贵**：到 160k 外矿毛收 5.40M，外矿角色孵化 2.54M（reserver 1.16M、remoteHauler 0.87M、remoteMiner 0.51M），净 2.86M，毛/孵 2.1；这还没算外矿里的容器/道路建造（12.5 万）。白名单外矿的源利用率约 60%，缺口近一半来自"分配了却几乎没预定、没挖"的房（下文）。
- **地面衰减是最大的单项损耗**：RCL4 阶段地面平均堆着 19k 能量（峰值 32.6k），其中己方房 13.7k 里 88% 在刚占的新房（W33S8 平均 6.3k），母房自己只有 1.6k——是新房没有 hauler，不是母房运力；RCL5 平均 12k，83% 在外矿（峰值 26k 时外矿占 74%），因为容器缺或 remoteHauler 不够。按"每堆 ≥1/tick、每 1000 能量 1/tick"估算衰减 0.82M / 0.89M，占收入 16% / 6%；残差（31% / 25%）里其余是修理、塔、带着能量死掉的 creep 和账本漏记（推算，见"局限"）。
- **两个新房因容器衰减陷入收入死锁**：W33S8 在 tick 101k 三个容器同时到寿命消失（25k tick 无人修），之后进度冻在 93,737 整整 40k tick，采集 0.4/tick；tick 141.8k 降到 RCL3，引擎把进度记成"旧进度 + 下一级的 90%"，一次升级就弹回 RCL4（进度 80,500），165.3k 再降——每个来回净亏 13,237 进度，且完全不产 CP。W35S7 在 124k 同样丢光容器，升级速率从 9.2 掉到 0.4/tick。这是 peer 在 88fe9e7 之后已修的那类问题（ea50051 / a58de3e / 0ce2933，外加核验后发现的"生存档 upgrader 卡住重建 builder"排序陷阱），基准给出了代价：一个房损失 ≥ 40k tick 和一级。
- **占领流水线在 tick 95k 后卡死**：大脑从 95,064 那轮起连续 16 轮都给 W34S9 发"占 W33S9"。W33S9 对其它 5 个母房都是 noRoute，但对 W34S9 大脑算出一条 3 跳路 W34S9→W34S10→W33S10→W33S9——W34S10/W33S10 是没有地形/出口情报的 highway 房，`route_hops` 把无情报房当作连通可穿越，而 W34S9 西边整列是墙，游戏内根本走不过去。`expansion` 从 95,067 起一直挂着这个目标，95k 后采样到的 claimer（176 次）和 pioneer（319 次）100% 站在 W34S9 里等到死，到 160k 烧掉 claimer 8.2 万 + pioneer 6.9 万；90k 后再无占领，GCL 12 的 4 个空位一直没用上。**眼下限制账号增长的不是 GCL（到 GCL13 还差 6,610 万 CP，约 78–88 万 tick），而是这条卡住的流水线。**

## 方法

- 世界：线上快照的 30 个真实地形房（W31–W36 × S5–S9），只播种控制器/源/矿/Source Keeper lair；W33S7 (23,21) 一个 300 能量 spawn，Memory 空，20000 tick 安全模式（与官方重生一致）；账号 CPU 140、GCL 12（与线上相同）；外部大脑每 5000 tick 一轮（线上每 5 分钟 ≈ 80 tick），允许占领。
- 账本全部从数据库侧读：采集 = 源 `invaderHarvested` 增量；升级 = 用户 gcl 点数增量（= 账号总 CP，引擎源码核对无 boost 时严格相等）；各房进度按控制器分账；孵化 = 首次见到的 creep 身体成本（引擎在 createCreep 当 tick 扣费并插入对象）；建造 = 工地进度；库存 = 建筑/creep/地面能量；spawn 自产按 1/tick 估。采样每 50 tick，升级 tick 线性插值，核验用 50 tick 区间夹逼后逐个吻合。
- 三种下限：A = 所需 / 20（母房两源全投控制器）；B = 所需 / 母房自家实际收入（两源 + 母房白名单里、且未被占下的外矿）；C = 所需 / 母房自家潜在产能（两源 + 自家外矿源，预定时按 10/tick）。**A 在有外矿之后不再是真上限，C 才是**；效率 = 下限 / 实际。

## 故障

- **容器衰减 → 收入死锁 → 降级**（W33S8、W35S7）：容器 250k 血、己方房每 500 tick 掉 5,000，25k tick 归零。丢容器后 `recovering` 每 ~500 tick 来回翻转：只剩 1 只 harvester 时 recovering=true 只孵 harvester（builder/hauler/upgrader 目标 0）；凑齐 2 只退出 recovering，1,250 的 upgrader 卡在队头，800 的 builder 轮不到；600 的往返式 harvester 送不回能量，采集 0.4/tick。W33S8 容器工地冻在 2,190/5,000 和 0/5,000 直到现在；W35S7 同样。
