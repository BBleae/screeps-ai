## 结论：排队成立，30k 内建不成；按正确性保留

单变量：`6d0cf2a`（SK 关）vs `a1fbfb4`（A + layout 把 storage/terminal/extractor/lab 提到道路和 extension 之前，lab 每轮最多 2 个，extension 还缺时留 1 个名额）。`a1fbfb4` 的 layout 补丁与部署分支 `fb63a0d` 逐字相同。快照 `db-storageab.json` @ 504,299，各 29,950 tick。

**主指标是一次性建筑的排队，不是 30k 内完工。**

| 房 | A 首次 terminal/lab 工地 | B 首次 terminal/lab 工地 | A 期末建成 | B 期末建成 | A 期末工地 | B 期末工地 |
|---|---|---|---|---|---|---|
| W33S7 RCL7 | +15,456 / +16,456 | **+456 / +456** | term 0 lab 0 | term 0 lab 0 | term 0/100k、lab×2 0/50k、spawn 9.2k/15k | term 0/100k、lab×4 0/50k |
| W34S7 RCL6→7 | **从未排队** | **开局就有** | term 0 lab 0 | term 0 lab 0 | 11 个 extension，无 term/lab | term 0/100k、lab×4 0/50k、ext×9 |
| W31S5 RCL6 | +9,956 / +9,956 | +12,456 / +12,956 | lab 3，term 36.6k/100k | lab 2（+1 座 47.8k/50k），term 0/100k | term 36.6k | term 0、lab 47.8k |
| W31S6 / W31S8 / W34S9 | 均有 term+lab 工地 | 同样有 | 0 座；lab 工地进度 0–28k | 0 座；lab 工地进度 0–25k | 各 1 term + 3 lab | 同左 |
| 全账号 extractor | 0 个工地 | 0 个工地 | 0 | 0 | — | — |

W34S7 是补丁要修的那条故障：A 组 30k 结束时 11 个工地全是 extension，terminal/lab **从未进队列**；B 组从第一份探针起就占着 1 个 terminal + 4 个 lab 工地。W33S7 把排队提前了约 15,000 tick。这两处足够证明"extension 还缺时一次性建筑排不上"是真的。

**完工在 30k 窗口里看不到。** 两组 terminal 建成数都是 0。lab 只有 W31S5 建成（A 3 座、B 2 座且第 3 座 96%），A 还先动手（+12,000 vs +17,500）。母房两组的 terminal/lab 工地进度始终是 0——builder 的 `sitePriority` 里它们和 extension 同档 10，按剩余进度从小到大，3,000 的 extension 永远排在 50,000/100,000 前面。这与补丁注释一致：提前放只让它们进队列，不改变建造顺序。extractor 两组都没放过工地，不是这一层的问题。

对照：88fe9e7 主跑在 **没有** 这个补丁的情况下，RCL7 的 834k tick 里仍然建成了 1 terminal + 6 lab + 1 factory + 第 2 spawn。所以旧顺序不是"永远建不成"，是"等 extension 配额吃完才轮到"。30k 分叉测的是排队，不是终态。

**反向安全：轻度的名额占用，不是 builder 被拉去啃贵建筑。**

- 建造/tick 31.4 → 27.6（−12%）。3k 窗口全程 B 组更低，符合"贵工地占名额、builder 仍在做便宜的"而不是"builder 去啃 10 万的 terminal"。
- extension 爬坡：W33S7 30→48 vs 30→44；W34S9 两边都到 40，A 在 +15k 到、B 在 +25k 到；W34S7 20→23 vs 20→22；W31S6 反而 B 更快（30→35 vs 30→38）。没有"extension 停摆"。
- 降级 0、错误 0。容器最低血量无系统性恶化。

**CP 中性。** 全账号 76.1 → 75.0。采集 195.6 → 185.0 是外矿分支（W33S6 净 3.7→1.2、W32S5 3.0→1.7），不是 layout。按 CP/收入：W33S7 36%→40%、W34S7 53%→64%、W31S6 44%→40%、其余持平。没有"提前放 terminal 就涨 CP"的信号，30k 里也没有 terminal 可启用。

**判决：保留，依据是排队正确性，不是本轮 CP。** 故障用例是 W34S7（A 组 30k 内一次性建筑进不了队列）。代价是工地名额被 0 进度的贵工地占住、extension 略慢、建造/tick 低一成，都可以接受。要看 terminal 建成 tick，需要比 30k 长一个数量级的窗口（一座 terminal 10 万进度，builder 优先 3,000 的 extension）。extractor 零工地是另一件事，本轮不判。
