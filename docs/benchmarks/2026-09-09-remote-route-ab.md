# 外矿供能与道路预算：最终 A2/F 对照

最终 F（`5d96ec4`）相比原版 A2（`f949cc9`），控制器净进度提高 10.11%，真实外矿交付提高 33.42%，期末地面能量减少 80.84%。完整实际孵化成本计入后，外矿窗口净回流由 -8592 改善至 -331，亏口减少 8261，但尚未转正。支持按发展优先发布正确性、供能与道路预算修复；不能宣称长期外矿盈利已经验证。

## 计量更正

旧 A/C/D/E 的 test-only wrapper 按 creep.name 永久去重。生产命名会复用死者名字，因此漏计替补成本；所有旧孵化费用与净现金数字撤回，不得继续使用。旧 CP、实际交付、建造/维修和掉落数据独立有效。原始数据与更正说明保留用于审计。

最终 A2/F 使用真实 engine creep.id 去重：无 ID 对象暂不计，首次出现有效 ID 即计身体费用，包括正在孵化的 creep；同名的新 ID 单独计费。保存每个出生的名字、ID、身体费用、角色、出生 tick 和 spawning 状态。微测试覆盖 undefined ID、同 ID 多 tick、同名两代及建造/维修拆分。

另直接执行当前私服引擎 `processor/intents/creeps/build.js` 验证：无 boost 的 1 WORK 建造一次增加 5 进度，消耗 5 energy，EVENT_BUILD.amount 和引擎 energyConstruction 统计均为 5。BUILD_POWER 表示每 WORK 每 tick 建造量，不能据此把 amount 除以 5。本场景无 boost，所以建造进度等于耗能。

## 路线及道路预算生效

F 的 W31S1/W32S1/W33S1 源路程分别为150/103/131，全部distanceVersion3、distanceIncomplete=false；控制器路程150/97/126，亦全部完整。W33S2源路程25、控制器36。全部drop缓存版本3。

线上取证显示：四次房间出口的路线使用maxRooms5或8仍可能失败，maxRooms16才得到完整150格。maxRooms限制探索房数，而不是最佳路径房数。routeLength与planRoute因此采用至少16探索房预算，保留maxOps10000及不完整路径25tick重试；旧drop缓存按母房/目标相位在25tick内迁移。

预算修复但尚无限制建造的 E，严格t3000 CP净进度31169，对旧A下降13.17%，建造/维修18125；真实完整路线激活了此前未生成的道路。F加入每趟50能量道路预算后，建造总量950，遥测maxTripSpent50且16次预算消费后的实际交付，恢复发展速度并减少地面积压。旧E孵化费用不可用，不能给出E现金对比。

F期末reserve为W31S1 958、W32S1 1451、W33S1 234、W33S2 330；A2分别397/1807/198/1751。没有逐tick reservation 历史，不能宣称零断档；仍需线上持续关注低余额及后继到达。CPU后段粗粒度均值A2 9.51、F 9.62，仅作为运行检查，不主张精确CPU优化收益。
