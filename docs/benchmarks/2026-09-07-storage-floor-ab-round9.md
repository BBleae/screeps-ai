## 结论：安全通过，但基准**无法确认**收益；修复按正确性保留

**修复实际作用于哪些房**（B 组的 `ctrlFeedBand` 遥测只在 storage 供能房写，A 组无此字段）：W31S8（触发 9,718 次）、W31S5（8,153）、W31S6（2,842）、W34S9（2,189）、W33S7（959）。未触发：W33S8、W34S7、W35S7——这三个房两组 CP 分别是 14.4/14.3、8.4/8.2、8.7/8.6，**作为对照组几乎完全一致**，说明两组的整体环境是可比的。

**五个受影响的房方向不一致**：W31S5 CP 3.0 → 6.2（CP/收入 15% → 32%，收入两组同为 19.0–19.1）、W33S7 14.4 → 15.7（但它的外矿到货同期 19.1 → 19.9，不能全归因）、W31S6 11.2 → 11.1、W34S9 11.8 → 11.4、**W31S8 5.4 → 3.5（CP/收入 21% → 13%，收入两组同为 26.2–26.3）**。合计 +2.1/tick，全账号 77.3 → 79.0（+2.2%），落在我们已测得的跑间发散范围内。

**W31S5 的分阶段数据是死区最直观的证据，但它同时也是唯一一个**：把 30k tick 切成两段看，A 组前 6,000 tick（storage 从 2 万往下花）CP 12.44/tick，之后 storage 停在 2,013 时**塌到 0.59/tick**——一个收入 19/tick 的房只产出 0.6 CP；B 组同段维持 **5.33/tick**。这正是"补给地板 = 取用底线 ⇒ 可取量恒为 0"的行为。但 W31S8 在同一段里是 A 5.50 / B 3.08，**方向相反**，两房的 storage 水位却几乎相同（2,013 vs 2,200）。所以死区机制在 W31S5 上可见，却不能推广成"修复必然提升 CP"。

**安全指标全过**：两组 0 次 emergencyHarvest；零 hauler 采样 W33S8 4/4、其余全 0；storage 最低点 W31S5 1,594/1,390、W31S8 1,700/1,700，**均未跌破 2,000 以下的危险区**（判据按"是否接近 0"而非"是否低于 A 组"）；容器最低血量 W31S8 145k/129k、W35S7 124k/102k，无系统性恶化。

**建议**：**保留修复，但依据是正确性而不是本轮的 CP 数字**。死区在代码上可证（`floor == reserve` ⇒ 可取量恒为 0），线上遥测 `ctrlFeedBand` 也是直接的决策事件证据（本轮基准里触发 959–9,718 次），而 30k tick 的 CP 差在这个量级上分不出信噪。若要量化收益，需要一个 storage 供能状态能长期维持的场景——基准里这些房很快建成 ctrl link 或把 storage 花空，storage 供能只是过渡态。

**一处更正**：我此前说"基准世界里没有深坑容器"是错的。W31S5 的容器在两组里都掉到过 **3,000 血（1.2%）**（A 组 tick 28,744、B 组 24,250），末态 16k / 249k。所以"深坑该交给 builder 还是塔"的问题在基准里**有**测试用例，不必额外播坑。

## 结论修正（按"是否真的塌进死区"分层后）

上面的"合计 +2.1、方向不一致"是**未分层的平均，稀释了信号**。把 30k tick 切成 3,000 tick 的窗口逐段看 CP/收入 与 storage 水位，五个受影响的房里**只有 W31S5 真的进过死区**：

| 房 | A 组（修复前）逐窗 CP/收入 | B 组（修复后） |
|---|---|---|
| **W31S5** | 79% → 47% → **4% → 16% → 3% → 1% → 0% → 0% → 0%**（最后 9,000 tick 每窗 **0.0 CP/tick**，storage 钉在 2,000） | 63% → 37% → 31% → 37% → 24% → 36% → 24% → 25% → **24%**（storage 2,047–2,502） |
| W31S8 | 20% → 36% → 36% → 36% → 45% → 30% → 20% → 34% → 26%（**从未塌陷**，storage 2,096–3,238） | 20% → 38% → 24% → 8% → 27% → 20% → 19% → 13% → 15% |
| W31S6 | 22% → 42% → 70% → 74% → 69% → 66% → 68% → 72% → 73%（storage 147–1,314，**在花不在囤**） | 26% → 50% → 71% → 71% → 72% → 65% → 68% → 61% → 73% |
| W34S9 | 47% → 27% → 46% → 79% → 62% → 78% → 67% → 74% → 72%（storage 211–7,284） | 20% → 19% → 54% → 71% → 73% → 68% → 73% → 74% → 82% |

**所以正确的读法是**：修复只对"storage 钉在取用底线上、CP 已经塌到 0"的房有效，而基准里符合这个条件的只有 W31S5 一个——它从**连续 9,000 tick 恒为 0.0 CP/tick**（同期采集 19/tick）恢复到稳定的 24–37%。一个收入 19 的房产出精确的 0，不是噪声能造成的，这与线上 W31S6 部署前连续三个采样 0.00 是同一现象。其余四房从未进入死区（storage 要么在花、要么水位高于底线），它们的方向散布属于跑间发散，**不该与 W31S5 平均**。

**修正后的判决**：修复对目标房类别有**大幅且结构性的**作用（把恒零产出变成稳定产出），对非目标房中性。原结论里"基准无法确认收益"应改为"**基准在唯一符合条件的房上确认了收益，样本量 n=1**"。
