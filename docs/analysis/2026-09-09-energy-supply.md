# 供能异常根因与联合修复（2026-09-09）

## 根因与改动

已与「优化 Link 搬运逻辑并部署」会话完成交接，保留其全部 Link/operator 改动。W33S3 是无 Link 的 RCL4 房，供能异常另有以下根因：

1. 非富余仓库被排除在 hauler 取货之外，仓库2059–3119闲置而孵化/控制器缺能。新增实际消费者兜底，保留2000储备、至少取50、同tick共享库存与消费者缺口预算，已取货不倒回仓库。
2. reserve替补提前量漏算60tick能量宽限，旧跨房距离缓存又偏短。补宽限、孵化、距离及裕量，并为多spawn使用保守几何下界。
3. `PathFinder.maxRooms` 限制探索房数，不能等同房间跳数。线上W31S1预算5/8失败、16成功150格；W32S1实际103格、W33S1实际131格。源、控制器、卸货候选及道路规划统一使用至少16探索房预算、10000操作上限；距离version3迁移，失败25tick重试，卸货旧缓存25tick错峰刷新，完整路径优先。
4. 空道路路线被判为已铺好，且原来只检查外矿房内道路。改为跨房全部路段完整覆盖检查；空路、缺视野或缺路不允许使用道路运输身体。
5. 外矿运输工优先取非空容器，忽略脚边足够装满的掉落。现在这种掉落优先，下一tick确认实际到账；不为小堆绕路。
6. 路线修通后，旧逻辑会让回程运输工停下来建完道路，甚至耗尽整趟货物。道路建设改为每趟最多50能量，下一tick核实实际消耗，实际卸货后才刷新；容器建设和维修保留原优先级。
7. 监控把两个端点容器为空写成“持续为空”。改为“两次采样为空”，不推断未采样时段。
